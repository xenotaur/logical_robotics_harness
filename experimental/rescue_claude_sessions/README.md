# Rescue Claude Sessions

Recovery tooling for Claude Code state stranded when a repository's *physical*
path changes while its *logical* path stays stable.

`plan.md` records the incident, the measurements, and the safety boundary.
This file is the design and the runbook: what this layer owns, what it must
never own, and the order in which to run it.

## Why this exists

Claude Code keys several persistence layers by the working-directory path
string:

> Claude Code stores transcripts as JSONL at
> `~/.claude/projects/<project>/<session-id>.jsonl`, where `<project>` is your
> working directory path with non-alphanumeric characters replaced by `-`.
>
> — [Manage sessions](https://code.claude.com/docs/en/sessions)

Moving the LRH and LCATS repositories out of Google Drive while leaving
symlinks behind gave each repository two path spellings, and therefore two
buckets — each with its own transcripts and its own `memory/`. Sessions started
from the new path read an **empty** memory corpus and never report a problem.

The governing invariant:

> When a project's physical repository path changes while its logical path
> stays stable, path-keyed agent state must be migrated to the canonical
> physical identity or intentionally retired. Symlinking the filesystem is not
> sufficient.

## Ownership boundary

This layer is a **migration/recovery layer**, not an archive. LRH already has
an archive and an identity index; duplicating either would create split-brain
retention.

| Layer | Owns | Hard invariant |
| :--- | :--- | :--- |
| `lrh sessions` | Durable transcript archive; `project/sessions/index.jsonl` | This tooling **never writes the index** — it is "committed and regenerated by observation, never hand-edited" |
| `rescue_claude_sessions` | Live-bucket topology: split detection, memory-corpus migration, redundant-copy removal | **Never** creates a durable archive; destructive steps require the LRH archive to already hold the copy |
| Neither | Claude Code's picker/resume behavior, desktop session history, `~/.claude.json` | Read-only. Diagnose, never mutate |

Two consequences, both load-bearing:

1. **`lrh sessions sync` must run before `archive_split_transcripts.py`.**
   Sync mirrors per *slug*, so a stale duplicate and its live counterpart are
   archived as separate entries and neither is lost. Moving the stale copy out
   of `~/.claude/projects` first would remove it from sync's view permanently.
2. **`snapshot_state.sh` output is rollback protection, not an archive.** It
   writes to `/private/tmp`, which the OS may reclaim.

`archive_split_transcripts.py` enforces (1) as a *precondition*, not as runbook
advice: it refuses to move any copy absent from LRH's durable archive. A tool
that refuses beats a document that reminds.

## Two lanes

Memory is migrated **once per repository** — it is slug state shared by every
session under that identity. Transcripts reconcile **per session**, because a
dormant session only forks a duplicate when it is first touched under the new
path. Cost therefore scales with repositories now, and with sessions only as
they are actually resumed.

```
REPO LANE (once per repository)
  move repo -> symlink -> mint canonical bucket -> snapshot ->
  audit -> migrate memory -> acceptance test
                    ^
                    |  contract: the canonical bucket must exist
                    v     before memory can migrate
SESSION LANE (lazily, per session as resumed)
  resume from canonical path -> fork occurs -> do the work ->
  lrh sessions sync -> archive redundant duplicate
```

### Repository lane

1. Move the repository; leave the logical symlink in place.
2. **Mint the canonical bucket** — start one session from the new physical
   path. `migrate_memory.py` deliberately skips projects whose destination
   bucket does not exist yet; this step is the inter-lane contract.
3. `./snapshot_state.sh --scope memory --fast`
4. `python3 audit_buckets.py` (add `--json` for a manifest)
5. `python3 migrate_memory.py` then `--apply`
6. Run the acceptance test below.

### Session lane

1. Resume the session from the canonical path. It forks a new-bucket copy.
2. Do the work.
3. `lrh sessions sync`
4. `python3 archive_split_transcripts.py` then `--apply`
5. For LRH work, record identity with `lrh prompt record-session-alias` /
   `lrh sessions link` — never by editing the index directly.

## Acceptance test for memory migration

File counts and hashes prove a *copy*, not *consumption*. The test reuses an
existing LRH convention: `lrh-work-remains`'s grounding rules already require a
session to "State the exact directory path checked (the `<project-slug>`
actually used)", precisely because "a forked or relocated session can end up
writing to a *different* project-slug directory than its predecessor without
either session noticing".

In a fresh session started from the canonical path, require both:

1. It names the **canonical** slug as its memory directory.
2. It summarizes a named `feedback_*` memory whose content is obtainable only
   from the migrated corpus.

Two independent assertions, both falsifiable. Until both pass, treat the
migration as unproven and keep the source corpus.

## Edge cases

- **Truncated slugs.** Claude Code truncates slugs past 200 characters and
  appends a hash of the full path, which cannot be reproduced here.
  `audit_buckets.py` flags them and refuses to auto-pair.
- **Non-LRH hosts.** No special case needed: `lrh sessions sync` scans all of
  `~/.claude/projects` and is host-agnostic for the raw mirror. Run it from the
  LRH checkout. `--no-require-archived` exists only for genuinely LRH-less
  environments.
- **Divergent duplicates.** Refused, reported, never auto-merged. A non-prefix
  duplicate holds unique content and needs human adjudication.

## `cmp` is not a prefix test

BSD `cmp -n <size> old new` reports `EOF on old` and exits non-zero when `old`
is a pure prefix of `new`, which reads as "they differ" when they do not. It
does so even at `-n <size-1>`. Compare a SHA-256 of the whole shorter file
against a SHA-256 of the longer file's first *size* bytes instead;
`bucketlib.is_byte_prefix` does exactly that.

## Tools

| Script | Role | Writes? |
| :--- | :--- | :--- |
| `bucketlib.py` | Shared bucket/slug/hash helpers | no |
| `audit_buckets.py` | Pairs, orphans, splits, latent risk; `--json` | no |
| `snapshot_state.sh` | Verified tar of projects + `.claude.json` | to `/private/tmp` |
| `migrate_memory.py` | Copy corpus forward, SHA-256 verify | `--apply` only |
| `archive_split_transcripts.py` | Move proven-prefix duplicates aside | `--apply` only |

Both Python mutators are dry-run by default and safe to re-run.

## Prior art check

**Duplication.** No existing implementation of bucket or path migration;
`path-keyed` and `memory corpus` return zero hits repo-wide. `lrh sessions
sync/discover/link` owns the archive half, which this design delegates to
rather than reimplements. No sibling repo or external library applies — the
layout is specific to Claude Code. **Verdict: proceed.**

**Demand.** No work item or backlog entry requests this.
`PROP-LRH-SESSION-ARCHIVE-SYNC` covers transcript archive and identity
reconciliation, not path-keyed state migration. Adjacent:
`WI-CODEX-EXPORT-DURABLE-ARCHIVE-DEFAULT` shares the durable-archive-first
principle — link, do not close. **Verdict: no closeout, one link offered.**

## Promotion policy

Everything here is provisional per `experimental/README.md`. The mutators
should stay that way: they encode reverse-engineered layout, and the docs warn
that "the entry format is internal to Claude Code and changes between
versions".

Only the **read-only audit** is a promotion candidate, as an extension to
`lrh sessions discover`, which already cross-references local transcripts
against the index — "and flags split project identities" is one step away.
Stage 3 of `WS-SESSION-ARCHIVE-SYNC` is its natural host; no Stage 3 work items
are filed yet.

## Open question this incident informs

`PROP-LRH-SESSION-ARCHIVE-SYNC` defers the archive-root location because "the
choice interacts with the user's backup and file-sync arrangements". This
incident — agent state corrupted by a cloud-sync-managed directory — is direct
evidence for that question and should be recorded against it.
