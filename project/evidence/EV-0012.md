# Session Archive Sync Closeout Baseline

This evidence records the metadata-only `lrh sessions report` baseline used to
reconcile `WS-SESSION-ARCHIVE-SYNC` closeout. It intentionally records counts,
reasons, and follow-up classifications only; it does not include raw transcript
bodies, raw export JSON, private archive paths, or secret-bearing data.

## Classification

- **Pending records (39):** records whose `session_transcript` is still
  `pending`. These are not treated as proof of transcript loss. They are
  metadata follow-ups: update the affected execution records when a durable
  backend pointer is known, or classify the backend as terminal `none` where
  no retrievable transcript exists. The current report groups them as 24
  `landed`, 13 `in_progress`, 1 `superseded`, and 1 `completed`.
- **Dangling records (87):** records whose pointer cannot currently be resolved
  through `project/sessions/index.jsonl`. The dominant reason is
  `claude-app host id is not present in project/sessions/index.jsonl` (85
  records). Two records use the placeholder `codex-app:current-task`, which is
  not a durable thread id. These are metadata/index coverage follow-ups, not
  new archive-command implementation blockers.
- **Unarchived records (75):** records with durable `codex-app:` pointers but
  no successful durable archive attempt. The report attributes all 75 to
  `codex-app thread id has no successful durable archive attempt`; the three
  affected thread ids account for 57, 9, and 9 records respectively. These are
  covered by existing Codex import/export follow-up work and can be reduced by
  dogfooding/importing the corresponding private exports without committing raw
  content.
- **Unsupported records (0):** no unsupported pointer schemes were reported in
  this baseline.

## Weekly Scheduled Sync

The weekly scheduled-sync closeout criterion is accepted as a documented setup
path, not as a repository-verifiable claim that a host-local launchd job is
currently loaded. `docs/reference/cli/sessions.md` documents
`lrh sessions schedule`, including how to render an inspectable weekly launchd
plist and how a human can inspect, load, and disable it. That is the appropriate
repo-level closeout state because launchd installation is local machine state
outside the control plane.

## Closeout Decision

`WS-SESSION-ARCHIVE-SYNC` is implementation-complete for the command surface
and capture mechanisms it governed: forward capture, sync/discover/link,
durable Codex defaults, nested artifacts, report, scheduled sync, closeout sync,
and Codex session id resolution have landed. The literal "zero post-Stage-1
gaps" reading of the workstream's report criterion is not true at this
baseline. The closeout state is therefore interpreted as:

- the implementation workstream is closed;
- the remaining report findings are classified archive-coverage and metadata
  follow-ups, not hidden implementation success;
- follow-up work remains proposed or resolved under the same workstream, most
  notably Codex rescue/import consolidation, Claude slug/index correctness, and
  archive-root/date-browsability decisions.

This preserves the invariant pressure of `lrh sessions report` while avoiding a
false current-state assertion that every post-Stage-1 record is already
archived and resolvable.
