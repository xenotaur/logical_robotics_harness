# Summary

Design proposal `PROP-LRH-SELF-REVIEW`: a `/lrh-self-review` skill that
dispatches a cold-context subagent to independently review a diff (before
a PR's first push) or a PR (as a post-ceiling substitute for a GitHub
bot retrigger), formalizing a pattern already used ad hoc, successfully,
four times in this project (PRs #447, #452, #457, #459).

# Result

Ran the `/lrh-proposal` skill's full interview/research/confirm-gate flow.
The interview questions were pre-answered from the preceding conversation
(user's explicit design decisions on trigger point, round-cap-gate
interaction, cost-tracking approach via occurrence-recording rather than
currency, and v1 scope limited to `/lrh-implement` + `/lrh-land`), rather
than re-asked.

Prior art check: no existing implementation — only a hypothetical mention
in `lrh-confirm-fixes/SKILL.md:419-438`'s escalation question, and the ad
hoc `Agent`-dispatch pattern used by hand in the four evidence PRs, never
packaged as a skill. Demand check found `WI-REVIEW-LANDED-CANONICAL-CHECK`
(proposed) explicitly excludes this from its own scope, naming it "a
separate, not-yet-filed future work item" — this proposal is that item's
design. `project/design/backlog.md`'s "Self-review-first tier..." entry
(written earlier this session) is the evidence base this formalizes.

Wrote 7 design decisions: (1) two trigger points — a single pre-push
diff-mode pass plus the existing post-ceiling PR-mode substitute, not a
per-push layer; (2) round-cap-gate.md interaction — the pre-push pass is
exempt from the ceiling by construction, since `round_state` is keyed by
PR URL and only exists once a PR does; substituted post-open rounds count
identically to bot rounds; (3) record occurrence (execution record per
run + a new CHAIN-NOTE `self_review_rounds=` field), not currency, since
no GitHub API exposes per-review credit cost; (4) never skip a PR's first
real bot round, grounded in `feedback_round_cap_self_review_alternative`'s
explicit caution that same-vendor self-review isn't blind-spot-equivalent
to an independent platform reviewer; (5) one skill, two invocation shapes
(local diff vs. PR URL), not two skills; (6) independent re-verification
of the subagent's own top finding is a mandatory documented step, not an
implicit habit; (7) a new single-skill workstream (`WS-SKILLS-SELF-REVIEW`),
following `WS-SKILLS-CONFIRM-FIXES`'s precedent rather than folding into
`WS-SKILLS-EXECUTE` (which is scoped to chain-*running* skills).

A live-verified fact discovered mid-session shaped Decision 1 directly:
opening a PR in this repo triggers automatic review from both
`copilot-pull-request-reviewer` and `chatgpt-codex-connector` within about
a minute with no explicit retrigger (observed on PRs #460 and #461,
opened with zero retrigger comments) — meaning the diff-mode pass must run
strictly before `gh pr create`, not merely before the first explicit
retrigger.

Presented the complete draft (frontmatter + full body) at the Step 5
confirm gate; user confirmed the proposed slug/ID/workstream names and
explicitly deferred the `PROP-LRH-LAND-EXECUTE` cross-reference mechanics
to WI-level detail rather than resolving it here.
