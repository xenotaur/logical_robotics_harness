# Result

- A crafted preserved_metadata_lines/preserved_top_level_lines entry naming a canonical key (e.g. authored_by) was silently accepted; splicing it in produced a duplicate YAML key that silently overrode the canonical value on re-parse. Fixed with new _validate_untrusted_preserved_lines(), also rejecting an embedded newline (which could forge additional frontmatter lines from a single bundle field).
- _write_memory_into_dir's and _import_records_into_dir's overwrite-auto-derive except clauses caught MemoryValidationError broadly, swallowing _UnsupportedPreservedKey (a readable destination with a genuinely unrepresentable extra, e.g. a block sequence) and silently dropping it instead of failing loudly, contradicting this module's established "never guess" principle. Fixed: _UnsupportedPreservedKey now re-raises; only a truly malformed/unreadable destination (UnicodeDecodeError, other MemoryValidationError) degrades to "nothing to preserve".
- A bundle written before this PR (full metadata dict, no preserved_*_lines fields) would silently lose its extras on import. Fixed with a fallback (_legacy_metadata_extra_lines) that recovers them from metadata when the new fields are entirely absent from the record -- safe because such a bundle's own export already required every value to be JSON-safe, so byte-fidelity was never at stake for this path.
- All three reproduced against the pre-fix code before fixing; 4 new regression tests added.
