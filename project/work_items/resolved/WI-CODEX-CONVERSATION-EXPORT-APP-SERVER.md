## Summary

Implement `lrh conversation export-codex-thread`, a production LRH adapter that
captures a Codex thread through the documented app-server `thread/read` route,
writes private raw JSON, and renders a private, non-authoritative Markdown
export compatible with the existing Codex conversation manifest and inspector.

## Problem / Context

The resolved Codex conversation exporter workstream delivered the manifest,
file-based adapter, inspector, and safe archive viewer, but it did not deliver
the original current-session exporter goal. The app-server spike in
`experimental/save_codex_threads/` demonstrated that a normal LRH subprocess can
read real Codex task data through `codex app-server --listen stdio://` and
stable `thread/read` with `includeTurns: true`.

This work item promotes that finding into reviewed package code without
depending on the experimental helper or scraping private Codex app storage.
It is the prerequisite for a `/lrh-codex-export` skill wrapper and any later
target-aware `/lrh-export` workflow.

### Duplication search

- In-repo: Related infrastructure exists in `src/lrh/conversations/` for
  manifests, file conversion, inspection, sensitivity scanning, and viewing. No
  production app-server export adapter or `export-codex-thread` CLI command
  exists. The only app-server probe is under `experimental/save_codex_threads/`
  and is not production code.
- Sibling repos: No sibling repository was identified as already implementing
  LRH-specific Codex app-server export.
- External libraries: No external library was identified that provides LRH's
  manifest, privacy, inspection, warning, and promotion-boundary behavior.
- Recommendation: Proceed by implementing a reviewed LRH adapter that reuses the
  existing manifest and inspector contracts.

### Demand search

- Work items: No existing proposed work item was found for this implementation.
- Proposals: Found
  `PROP-LRH-CODEX-APP-SERVER-CONVERSATION-EXPORT` and the prior adopted
  `PROP-LRH-CODEX-CONVERSATION-EXPORTER`.
- Backlog: Found related entries for experimental-code linkage guardrails and
  Codex executable trust/signature investigation.
- Recommendation: Keep those backlog entries linked but separate. This item
  should record trust warnings when applicable; it should not solve the full
  trust investigation.

## Scope

- Implement a library boundary for spawning a configured Codex executable with
  `app-server --listen stdio://` and issuing the JSON-RPC handshake.
- Implement `lrh conversation export-codex-thread` using stable `thread/read`
  with `includeTurns: true`.
- Write private raw JSON capture envelopes and render Markdown with
  `ConversationExportManifest` frontmatter.
- Reuse LRH's existing sensitivity scanner for rendered transcript text.
- Add tests with fake app-server subprocess or stream boundaries; real Codex
  app-server probes belong only in manual or smoke paths.

## Required Changes

1. Add `src/lrh/conversations/codex_app_server_export.py` or equivalent module
   with:
   - a small JSON-RPC app-server client for `initialize`, `initialized`, and
     `thread/read`;
   - explicit timeout, malformed-response, process-exit, and JSON-RPC-error
     handling;
   - capture-envelope construction with `capture_kind:
     lrh_codex_app_server_thread_read_capture`, schema version, timestamp,
     command metadata, request metadata, response envelope, and warning list;
   - raw JSON write behavior that hashes the exact bytes written.
2. Add CLI dispatch for `lrh conversation export-codex-thread` in
   `src/lrh/cli/main.py`.
3. Render Markdown using the existing manifest contract with
   `source_adapter: codex_app_server_thread_read`, `source_id` set to the Codex
   thread id, and `source_sha256` set to the raw JSON hash.
4. Map observed item types:
   - render `userMessage` and `agentMessage` as transcript sections;
   - render `fileChange` as path/kind/status metadata without reading file
     contents;
   - summarize `webSearch` metadata by default;
   - omit or explicitly gate `reasoning` summaries and record a warning;
   - render `contextCompaction` as an explicit continuity marker;
   - render unknown item types as metadata-only placeholders and record a
     warning.
5. Add docs to `docs/reference/cli/conversation.md` describing command usage,
   privacy posture, raw JSON handling, sensitivity scanning limits, trust
   warnings, and manual dogfood expectations.
6. Add focused tests for fake app-server handshake, success, app-server errors,
   malformed responses, timeout or process exit, renderer mappings, warning
   generation, manifest statistics, and inspector compatibility.

## Non-Goals

- Do not import from `experimental/save_codex_threads/`; use it only as design
  evidence.
- Do not scrape `.codex` files, ChatGPT app storage, or other undocumented
  storage internals.
- Do not print raw transcript text to stdout or stderr by default.
- Do not commit real raw transcript data or generated private conversation
  exports.
- Do not require experimental app-server APIs in the first production adapter.
- Do not implement `/lrh-codex-export` or target-aware `/lrh-export` in this work
  item.
- Do not resolve the full Codex executable trust investigation unless a blocking
  safety issue appears during implementation.

## Acceptance Criteria

- `lrh conversation export-codex-thread --thread-id ID --out EXPORT.md --raw-out
  RAW.json` creates private raw JSON and manifest-backed Markdown from a Codex
  app-server `thread/read` response.
- Generated Markdown records `source_adapter: codex_app_server_thread_read`,
  `source_tool: codex`, `source_id: ID`, `privacy: private`, and
  `authority: non_authoritative_context`.
- The command never prints raw transcript text by default and reports only
  metadata such as output paths, privacy, sensitivity, warnings, turn counts,
  item-type counts, and source hash.
- Renderer handles observed item types `userMessage`, `agentMessage`,
  `reasoning`, `fileChange`, `webSearch`, and `contextCompaction`, recording
  manifest warnings for omitted, summarized, interrupted, compacted, or unknown
  data.
- Focused unit tests cover fake app-server handshake, successful thread reads,
  malformed app-server responses, app-server errors, timeout or exit behavior,
  renderer mappings, warnings, and manifest statistics.
- `lrh conversation inspect-export` accepts an export generated by the new
  adapter.
- Documentation explains CLI usage, private raw output handling, sensitivity
  scanning limits, trust warnings, and manual dogfood expectations.

## Risk Notes

- Local Codex executable trust remains ambiguous after the spike. Production code
  should record trust warnings when diagnostics are ambiguous, but this work item
  should stop and alert the user if a new safety issue resembles the macOS
  malware-block incident.
- Stable `thread/read` is complete but not paged. Very large sessions may need a
  later experimental paged adapter using `thread/turns/list`.
- Reasoning summaries, file paths, and web-search metadata can expose sensitive
  information. The renderer must make inclusion/omission policy visible through
  manifest warnings.
- Live Codex tasks can change while exporting. The capture envelope should record
  timestamps and status counts so later readers can evaluate completeness.

## Dependencies / Order

viewer work from `WS-LRH-CODEX-CONVERSATION-EXPORTER`. It should land before any
`/lrh-codex-export` skill wrapper so the skill can call a tested CLI instead of
duplicating capture logic.
